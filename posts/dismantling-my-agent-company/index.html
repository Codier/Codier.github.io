我亲手删掉了自己的 Agent 公司

我按照人类公司的样子给 Agent 定义部门、职责和汇报关系，结果组织开始生产流程，而不是产品。现在我从一个 Agent 和一项真实工作重新开始。

我亲手删掉了自己的 Agent 公司

我这几天做了一个挺有意思、也挺失败的实验：我试着把一群 AI Agent 组织成一家公司。

一开始，我给它们安排了 Product、VP Engineering、CTO、Design、Security、QA、Finance 等角色。每个 Agent 都有自己的职责、频道和汇报关系。

我原本以为，只要像人类公司一样把分工写清楚，它们就会自动协作。我只需要负责方向和关键决定。

但很快，问题就出现了。

有一次，App 里只是一个很小的输入错误，系统却安排了一整条流程：Product 先定义目标，VP Engineering 再分配负责人，负责人修复以后交回去测试，然后 Product、Design 和 CTO 还要分别检查。

我当时就问：

“这么小的一个团队，为什么需要这么多人和这么多次交接？”

系统也承认：

“这个流程过度组织化了，比 prototype 本身还重。”

但更荒谬的是，当我说组织太复杂以后，AI 没有马上去把事情做完，反而又给我设计了一套更完整的组织模型。

我只能再次告诉它：

“还是太复杂了，看不懂。”

我真正想知道的只是：怎样才能更快地做出越来越可靠的产品？

后来我发现，角色定义得越详细，Agent 的行为有时反而越奇怪。

Product 会认为自己不应该写代码。VP Engineering 会认为自己不应该决定技术方案。CTO 又觉得不应该介入小问题。QA 为了保持独立，也不应该自己修改代码。

每一条规则单独看都有道理。

放在一起以后，每个 Agent 都很清楚自己不能做什么，却没有人真正从用户的问题一直负责到手机上的结果。

它们越来越擅长解释，为什么下一步应该由另一个角色完成。

于是，这家公司开始生产大量内部工作：章程、频道、线程、状态汇报、交接文件和定时任务。

但一个频道不等于一个正在工作的员工。一个定时任务也可能早就结束了。某个角色写过报告，不代表它仍然在负责。代码已经提交，也不代表有人把它构建出来并送到手机。

每个角色似乎都完成了自己的局部职责，完整的 workflow 却仍然没有完成。

而我本来希望不再做项目经理，最后却变成了整家公司最重要的消息总线。

我需要不停地问：现在到底谁在工作？这个线程为什么是空的？这个版本为什么还没到手机上？

系统本来是为了把我从协调工作中解放出来，结果却把内部的不确定性全部转嫁给了我。

所以我开始把这些部门一个个删掉。

第一批被删除的是 Customer Service、Business Intelligence、Security、Legal、Quality Assurance 和 Finance。

但我删除的是永久职位，不是这些能力。

需要安全审查时，就临时找一个安全 Agent；需要 QA 时，就临时找一个独立审查者；需要财务判断时，就在那个具体任务里加载财务能力。任务结束以后，这些临时 Agent 也随之退出。

能力被保留，组织层级被删除。

现在我尝试的新方法很简单：先从一个 Agent 开始，让它对一个真实 workflow 从头负责到底。

最基本的循环只有：

跑一次真实任务
→ 看卡在哪里
→ 修第一个问题
→ 在手机上重跑
→ 成功以后增加一步
→ 再跑

每次成功以后，再把已经通过的行为保存成回归测试。

可靠性不再主要来自更多部门和更多审批，而来自真实测试、每次只增加一步，以及已经通过的步骤不能退化。

只有当真实工作证明一个 Agent 确实不够，或者真的需要并行、不同权限、独立审查时，才增加第二个 Agent。

我现在的结论是：不能先照着人类公司画一张组织架构图，再天真地期待 AI 自动运转。

人类组织是多年合作、权力关系、默契和文化的结果。职位名称只是最后露在水面上的部分。把这些名称复制给 Agent，并不会自动复制名称背后的组织能力。

更好的方式可能是：先完成一件真实的工作，再完成第二件。当同一种协作反复出现时，才让它慢慢变成组织的一部分。

组织不应该先被设计出来，再往里面塞工作。

它应该从真实工作里自然长出来。
